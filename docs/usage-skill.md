# 方式一：Claude Code Skill 完整流程

> 这是 `README.md`「使用方式 → 方式一」的完整图文走查。Skill 模式由 Claude 逐阶段问你确认，适合一步步跟着走。

Skill 启动后，Claude 先检查模型配置通不通，再检测你当前的数据状态——有没有简历、有没有已爬取的岗位 CSV——并据此给出路径选项，由你选一条。

![Step 1: Claude 根据你的状态选择工作流路径](../images/01.png)

## 四条路径

| 路径                      | 触发条件                    | 流程                                                        |
| ------------------------- | --------------------------- | ----------------------------------------------------------- |
| **路径 A** ✨ 简历驱动爬取 | 你有简历、还没爬过岗位      | 上传简历 → 自动推断搜索参数 → 精准爬取 → 匹配 → 投递 |
| **路径 B** 匹配现有数据   | 已有岗位 CSV 数据           | 上传简历 → 加载已有岗位 → 匹配 → 投递                       |
| **路径 C** ✨ 预设重放     | 已有保存的预设参数          | 上传简历 → 加载预设 → 补齐缺失参数 → 精准爬取 → 匹配 → 投递  |
| **路径 D** ✨ 仅简历编辑器 | 没有简历文件，想先写/改简历 | 打开内置 ShowCV 简历编辑器 → 写完后重新进入 A/B/C |

**每条路径都从解析简历开始。** 岗位怎么搜、怎么打分、招呼语怎么写，全部依赖简历里的信息，所以「先爬后匹配」不是一条支持的顺序——没有简历，参数只能靠瞎猜。

**路径 A 是最智能的方式**：简历里已经包含你的技能方向、工作经验和期望城市，让简历告诉系统该搜什么，而不是盲猜。爬出来的岗位天然与背景对口，匹配命中率更高。

**路径 C 复用上次确认过的预设参数**：经验筛选、薪资、公司规模、最低岗位数等搜索参数在首次确认后已保存为预设，再次使用时直接重放即可；缺失的参数会自动询问补齐后才开始爬取。适合反复在同一方向求职的场景。

**路径 D：内置 ShowCV 简历编辑器**：还没有简历时，可以用内置的 ShowCV 编辑器直接在浏览器里排版、写、改简历并实时预览。写完后不必导出 PDF，编辑器里的 Markdown 可直接当简历喂给 `parse`，再回到 A/B/C 继续匹配与投递。

编辑器地址默认 `http://127.0.0.1:3090`（端口被占时自动往后找，以启动时打印的那行 `SHOWCV_READY` 为准）。

![Step D: 内置 ShowCV 简历编辑器](../images/showcv-editor.png)

## 阶段 1：上传简历 & 智能推断搜索参数

```
用户: [上传简历文件]

Claude: 📋 根据你的简历推断：
        - 搜索关键词：Python, 后端开发, AI应用开发, RAG
        - 目标城市：杭州
        - 经验筛选：应届生, 1年以内
        - 薪资筛选：5-10K, 10-20K
        是否按以上参数开始爬取？
```

![Step 3: 自动推断爬取参数 + 手动确认未知参数](../images/auto-infer-params.png)

模型深度解析简历内容，提取技能栈、工作年限、期望城市等关键信息，自动映射为 BOSS 直聘的搜索筛选条件。可推断的自动填好，**未知的参数单独问你确认**——你只需确认或微调，无需逐个手填。

爬取前 Claude 会把本轮要用的**经验 / 岗位类型 / 薪资 / 公司规模**等筛选参数汇总给你一次性确认，避免中途反复打断。确认后的参数写进 `crawl_params.json`，爬取和匹配都从这一份文件取值。

![Step 4: 手动确认本轮使用的筛选参数](../images/manual-confirm-params.png)

爬虫自动去重（基于 `link` 字段），把岗位详情写入 `assets/post_data/**.csv`。以关键词 "Python" + 城市 "杭州" 为例，通常可获取 45+ 个有效岗位。

爬取结束后，Claude 会对照你设定的**最低岗位数量（min_count）**检查结果。爬到的数量不足时会主动停下问你——**换关键词、放宽条件、还是接受现状**——而不是闷头往下跑。

![Step 5: 爬取数量不足，手动确认岗位下限参数](../images/manual-confirm-mincount.png)

![小于你设定的最低岗位数](../images/03所选城市无岗位.png)

## 阶段 2：登录检测 & 岗位爬取

首次使用需要先在你的 Chrome 里登录 BOSS 直聘。脚本会打开浏览器并**暂停等待你手动登录**，登录成功后 cookie 持久化，后续无需重复登录，随后自动爬取数据。

## 阶段 3：智能匹配 & 评分排名

系统拿你的简历和每个岗位的招聘信息逐项比对，按几项标准打分，最后告诉你这个岗位该不该投、能不能投。

**它比什么？** 就像 HR 挑人，逐项看：

1. **钱够不够（20 分）**——重合越多分越高；比你要的低就分低；比你要的高算「可以冲一冲」，给点分但不给满分。
2. **经验够不够（20 分）**——岗位写「3-5 年」，你实际干了几年一对就知道。够→满分；差一点→扣分；差太多→低分；岗位写「经验不限/应届」→直接满分。
3. **学历够不够（15 分）**——学历排等级（博士>硕士>本科>大专>中专）。岗位要求本科你有本科就达标满分；要求硕士你只有本科就是硬伤，直接 0 分。
4. **技能对得上几样（30 分）**——你简历的技能拿到岗位要求里搜，每对一个 +5 分。它认同义词：你写「k8s」=岗位的「Kubernetes」，「大模型」=「LLM」。对了 6 样封顶。
5. **职位名字沾不沾边（20 分）**——比如想干「AI 应用开发」，岗位名带「AI」或「开发」就加分。

**打分只是参考，另一套「能不能投」的判断才关键。** 有一组硬规矩，踩到任何一条直接判「别投」：

- 学历卡死你（岗位硬要硕士，你只有本科）
- 经验差 3 年以上
- 薪资离你期望差 8K 以上

没踩硬规矩、且各项都满足 → 直接投；否则 → 改一改简历再投。

**最后分四档**：能直接投的优先投 / 改改简历能投的给优化建议（如「多强调 RAG 实战」「把项目成果写具体点」）/ 不推荐但留在报告里 / 直接丢弃不在报告显示。

**深度模式**：上面的打分是固定公式，快但死板。深度模式再让模型把岗位描述和你的项目读一遍，看是否真对口（如你做过「客服机器人」、岗位要「智能问答」，光靠关键词搜不出这层意思）。准但费 token——所以先用公式粗筛一遍（`--top N`），只对中奖岗位做深度分析；中途能 `--resume` 接着跑，不重复花钱。

同时生成 Bauhaus 风格 HTML 可视化报告，含所有岗位的匹配度卡片、分类统计图表和投递状态。

## 阶段 4：确认投递哪些岗位 & 生成材料

Claude 把榜单和每个岗位的匹配理由列给你，由你决定**投哪些岗位、投几个**——这是防止误投的第一道确认。投递范围、招呼语生成方式、图片生成方式三个独立选项在一次提问里一起给你，每个可单独选择后一次性确认：

| 可选项             | 可选值                             | 说明                                                         |
| ------------------ | ---------------------------------- | ------------------------------------------------------------ |
| **投递哪些岗位**   | `全部合格岗位` / `我来选` / `取消` | 投合格岗位全部，或手动挑选（按序号，`--only 1,3,5-7`）；取消则终止本次投递 |
| **招呼语生成方式** | `自定义` / `默认` / `AI生成`       | 自定义=输入一段全岗位共用；默认=用内置模板；AI生成=逐个岗位调模型，结合该岗位 JD 与你的简历亮点生成个性化招呼语 |
| **是否发送图片**   | `自定义上传` / `AI调整` / `不发送` | 自定义上传=用你提供的简历图片；AI调整=以你的简历为基底，针对每个岗位定制优化并生成不含个人信息的简历图片；不发送=只发文字招呼语 |

![Step 6: 手动确认投递哪些岗位](../images/投递范围.png)

![Step 6: 手动确认投递哪些岗位](../images/manual-confirm-send-image.png)

投递前，系统会为每个岗位**自动生成一份不含个人信息的简历图片**（只保留技能、项目、教育等求职信息，隐去姓名/电话/邮箱等隐私），并针对该岗位做定制优化——既方便持续投递，又避免简历图片被随意分享时泄露隐私。

![Step 7: 自动生成不含个人信息的简历图片](../images/auto-gen-resume-image.png)

## 阶段 5：确认发送 & 自动投递

每个岗位会生成一份**个性化招呼语 + 简历图片**。发送前需要你确认——这是第二道、也是投递前最后一道确认。产物在 skill 的 `assets/<时间戳>/deliver` 下；最简单的方式是让 Claude 用 `/btw 生成的简历和图片在哪里？` 指给你。

![Step 9: 自动发送简历图片 + 招呼语](../images/manual-confirm-jobs.png)

![Step 8: 自动调整简历图片](../images/auto-adjust-resume-image.png)

用户确认后，DrissionPage 自动打开浏览器、进入岗位详情页、发送招呼语、上传简历图片。每次投递间隔 3-5 秒以规避反爬，结果记录到 `apply_log.json`。

![Step 9: 自动发送简历图片 + 招呼语](../images/auto-send-image-greeting.png)

![投递结束](../images/delivery-done.png)
